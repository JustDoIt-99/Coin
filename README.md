## 프로젝트 소개

## 주문/체결 흐름

### 시장가 매수 주문

시장가 매수는 Upbit **매도 호가를 순차적으로 소진하며 체결 수량과 체결 금액을 계산한 뒤, 이를 사용자 자산과 거래 내역에 반영**합니다.  

<img width="520" height="736" alt="image" src="https://github.com/user-attachments/assets/2c2be1a4-ee52-42af-9077-5a382df998e2" />

1. 시장가 매수 주문이 들어오면 먼저 **사용자의 KRW 자산 잔고를 확인**합니다.
2. Upbit Orderbook의 매도 호가를 순차적으로 반영해 실제 체결량과 총 체결 금액을 계산하고, 이를 바탕으로 평균 체결가를 산출합니다.
3. 이후 트랜잭션 내부에서 KRW 자산을 행 잠금(Lock)으로 다시 조회해 실제 체결 금액만큼 차감하고, 전체 체결 수량을 반영하여 평균 매수가를 갱신합니다.
4. 체결 결과는 거래 내역과 자산 변동 이력에 함께 저장됩니다.
5. 마지막으로 자산 갱신 이벤트로 체결 이벤트를 각각 발행해 클라이언트에 변경 사항을 전파합니다.  


### 시장가 매도 주문

시장가 매도는 Upbit **매수 호가를 순차적으로 소진하며 체결 수량과 체결 금액을 계산한 뒤, 이를 사용자 자산과 거래 내역에 반영**합니다.  

<img width="522" height="729" alt="image" src="https://github.com/user-attachments/assets/08cbe80a-be79-475b-9754-ac14dd6f9271" />

1. 시장가 매도 주문이 들어오면 먼저 **사용자의 코인 자산 보유 수량을 확인**합니다.
2. Upbit Orderbook의 매수 호가를 순차적으로 반영해 실제 체결 수량과 총 체결 금액을 계산하고, 이를 바탕으로 평균 체결가를 산출합니다.
3. 이후 트랜잭션 내부에서 코인 자산과 KRW 자산을 행 잠금(Lock)으로 다시 조회한 뒤, 코인 자산에서는 전체 체결 수량만큼 차감하고 KRW 자산에는 실제 체결 금액만큼 반영합니다.
4. 체결 결과는 거래 내역과 자산 변동 이력에 함께 저장됩니다.
5. 마지막으로 자산 갱신 이벤트와 체결 이벤트를 각각 발행해 클라이언트에 변경 사항을 전파합니다.

### 지정가 매수 주문
<img width="772" height="540" alt="image" src="https://github.com/user-attachments/assets/bb73f9d8-3cc7-4f89-b6dc-f914f37f756e" />

1. 지정가 매수 주문이 들어오면 먼저 사용자의 **KRW 자산 잔고를 확인**하고, 주문 수량과 지정가를 기준으로 잠금 금액을 계산합니다.  
2. 이후 사용자의 KRW 자산에서 해당 금액을 즉시 차감하는 대신 `lockedBalance`로 이동시켜 체결 대기 자금으로 잠금 처리합니다.  
3. 잠금 처리에 성공하면 지정가 매수 주문을 `PENDING`상태로 저장하고 KRW 자산의 잠금 이력을 함께 기록합니다.  
4. 이후 실시간 현재가가 사용자가 지정한 매수 가격 이하가 되면, 체결 가능한 `PENDING` 주문을 조회해 잠금된 KRW를 실제 체결 금액만큼 사용하고 남은 금액은 환불합니다.  
5. 마지막으로 대상 코인 자산에 체결 수량과 평균 매수가를 반영하고, 거래 내역과 자산 변동 이력을 저장한 뒤 자산 갱신 이벤트와 체결 이벤트를 발행해 클라이언트에 변경 사항을 전파합니다.    

### 지정가 매도 주문
<img width="792" height="546" alt="image" src="https://github.com/user-attachments/assets/ca41836b-5801-41c5-8294-4745f7a116a4" />

1. 지정가 매도 주문이 들어오면 먼저 사용자의 **코인 자산 보유 수량을 확인**하고, 주문 수량과 지정가의 유효성을 검증합니다.
2. 이후 매도할 코인 수량만큼 자산을 즉시 차감하는 대신 `lockedBalance`로 이동시켜 체결 대기 물량으로 잠금 처리합니다.
3. 잠금 처리에 성공하면 지정가 매도 주문을 `PENDING` 상태로 저장합니다.
4. 동시에 코인 자산의 잠금 이력을 기록하고, 주문 생성 이벤트를 통해 마켓별 최소 매도 지정가 인덱스를 갱신합니다.
5. 마지막으로 자산 갱신 이벤트를 발행해 클라이언트에 변경 사항을 반영합니다.
